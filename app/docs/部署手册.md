# 桥牌汇 BridgeHub · 部署手册

> 适用版本：**v1.7.0**（前后端一体 + Nginx 反代架构）
> 目标环境：Ubuntu 22.04 / 24.04 LTS（本文以 24.04 为准）
>
> **v1.7.0 更新要点**
> - 新增 `server/security.ts`：请求体限制、安全响应头、IP 限流、WebSocket 接入限流
> - **务必**在新机器上确认 `TRUST_PROXY=1` 已生效（见 5.5 节），否则限流会误伤全体用户
> - `/ws` 的 Nginx 转发头已补全（Nginx 的同名指令继承陷阱，见 5.5 节）
> - 新增 IMP 计分支持，无需额外配置

---

## 1. 架构总览

```
用户浏览器（手机 / 平板 / PC）
        │
        ▼  TCP 9100（唯一对外 Web 端口）
┌─────────────────────────────────────┐
│ Nginx 1.24（systemd: nginx.service）│
│  /        → 反代后端（前端页面）     │
│  /assets/ → 反代 + 30 天缓存 + gzip │
│  /api/    → 反代（REST 账号接口）    │
│  /ws      → 反代 + WebSocket 升级    │
└──────────────┬──────────────────────┘
               ▼  127.0.0.1:8100（仅回环）
┌─────────────────────────────────────┐
│ BridgeHub 后端（systemd: bridgehub）│
│  Node 22 + Express 5 + ws           │
│  · dist/         前端静态产物        │
│  · dist-server/  后端 bundle        │
│  · /var/lib/bridgehub/  数据目录     │
│    ├─ users.json   账号与会话        │
│    └─ daily.json   每日双人赛成绩    │
└─────────────────────────────────────┘
```

对外防火墙（ufw）只放行两个端口：

| 端口 | 用途 |
| --- | --- |
| 22/tcp | SSH 管理 |
| 9100/tcp | Web 访问（Nginx） |

后端的 8100 端口仅监听本机回环，外部不可直连。

## 3. 全新部署（在一台干净的 Ubuntu 上）

### 3.1 准备发布包（在开发机上执行）

```bash
cd app
npm install                 # 首次需要
npm run build               # 前端：tsc 类型检查 + vite 构建到 dist/
npm run build:server        # 后端：esbuild 打包到 dist-server/index.js

# 组装发布包
rm -rf release bridgehub-release.tar.gz && mkdir -p release
cp -r dist release/dist
cp -r dist-server release/dist-server
cp deploy/bridgehub.service release/
cat > release/package.json <<'EOF'
{
  "name": "bridgehub-server",
  "private": true,
  "type": "module",
  "scripts": { "start": "node dist-server/index.js" },
  "dependencies": { "express": "^5.2.1", "ws": "^8.21.3" }
}
EOF
tar -czf bridgehub-release.tar.gz -C release .
```

### 3.2 上传到服务器

```bash
scp bridgehub-release.tar.gz deploy/setup-bridgehub.sh deploy/setup-nginx.sh deploy/nginx.conf user@<服务器IP>:/tmp/
# 注意：nginx.conf 上传为目标脚本期望的文件名
ssh user@<服务器IP> 'mv /tmp/nginx.conf /tmp/bridgehub-nginx.conf'
```

### 3.3 执行部署脚本（服务器上，需 sudo）

```bash
# 第一步：应用本体（装 Node 22 → 解压到 /opt/bridgehub/app → 装依赖 → 注册 systemd）
sudo bash /tmp/setup-bridgehub.sh

# 第二步：Nginx 反向代理（装 nginx → 站点配置 listen 9100 → 防火墙放行 9100）
sudo bash /tmp/setup-nginx.sh
```

两个脚本都是**幂等**的：重复执行只会更新到最新发布包并重启服务。

### 3.4 验证

```bash
curl http://127.0.0.1:9100/api/health
# 期望输出：{"ok":true,"name":"BridgeHub","time":"..."}
```

浏览器访问 `http://<服务器IP>:9100/` 即可。

## 4. 日常更新版本

代码更新后，只需在开发机重新执行 3.1（打包）→ 3.2（上传）→ 然后服务器上：

```bash
sudo bash /tmp/setup-bridgehub.sh
```

脚本会重新解压、安装依赖并 `systemctl restart bridgehub`。Nginx 配置无需变动。
**用户数据不受影响**（数据在 `/var/lib/bridgehub/`，不在应用目录内）。

## 5. 运维操作

### 5.1 服务管理

```bash
sudo systemctl status bridgehub      # 后端状态
sudo systemctl restart bridgehub     # 重启后端
sudo journalctl -u bridgehub -f      # 实时日志
sudo nginx -t                        # 校验 nginx 配置
sudo systemctl reload nginx          # 热加载 nginx
```

### 5.2 数据备份与迁移

只需备份数据目录中的两个文件：

```bash
sudo cp /var/lib/bridgehub/users.json /var/lib/bridgehub/daily.json ~/backup/
```

迁移到新服务器：先完成全新部署，再把这两个文件覆盖到 `/var/lib/bridgehub/`，
`sudo systemctl restart bridgehub` 即可。

### 5.3 环境变量（改 `/etc/systemd/system/bridgehub.service` 后需 `daemon-reload` + `restart`）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8100` | 后端监听端口（配合 nginx 无需改） |
| `BRIDGEHUB_DATA` | `server/data` | 数据目录，生产为 `/var/lib/bridgehub` |
| `BOT_BID_MS` / `BOT_PLAY_MS` / `TRICK_CLEAR_MS` | `650` / `750` / `1100` | AI 行动节奏（毫秒），压测时可调小 |
| `TRUST_PROXY` | 未设置（不信任） | **反代部署必须设为 `1`**，否则客户端 IP 全为 `127.0.0.1`，限流失效且误伤全体用户 |
| `BEHIND_HTTPS` | 未设置（不发送） | 设为 `1` 后下发 `Strict-Transport-Security` 头。确认全站 HTTPS 后再开启 |
| `JSON_LIMIT` | `32kb` | REST 请求体大小上限，超限返回 413 |
| `AUTH_RATE_MAX` / `AUTH_RATE_WINDOW_MS` | `20` / `300000`（5 分钟） | 注册/登录等认证接口的单 IP 配额 |
| `API_RATE_MAX` / `API_RATE_WINDOW_MS` | `120` / `60000`（1 分钟） | 其余 REST 接口的单 IP 配额 |

### 5.4 内置安全加固（v1.7.0 起）

后端新增 `server/security.ts`，**无需额外依赖**，实现以下防护：

| 防护项 | 实现 |
| --- | --- |
| 请求体限制 | `express.json({ limit })`，默认 32KB，超限返回 HTTP 413 |
| 安全响应头 | `X-Frame-Options`、`X-Content-Type-Options`、`Content-Security-Policy`、`Referrer-Policy`、`Permissions-Policy`、`COOP`/`CORP` |
| 技术栈隐藏 | 移除 `X-Powered-By` |
| HSTS | 仅在 `BEHIND_HTTPS=1` 时下发，避免误配导致站点被强制跳转 HTTPS 而打不开 |
| REST 限流 | 按 IP 的滑动窗口；超限进入指数退避惩罚期（30 秒起，最长 30 分钟），响应带 `Retry-After` 与 `X-RateLimit-*` |
| WebSocket 限流 | 单 IP 每分钟最多 30 条新连接、10 次认证失败；超出直接拒绝握手 |
| 账号枚举防护 | 登录失败一律返回「用户名或密码不正确」，不区分账号是否存在 |

> **重要**：上述所有限流均以**真实客户端 IP** 为依据。后端部署在 Nginx 之后时，
> 必须同时满足两个条件才能取到真实 IP，缺一不可：
>
> 1. Nginx 转发了 `X-Forwarded-For`——且 **`/ws` 块内必须重复声明**（Nginx 规定:location 内一旦自定义
>     `proxy_set_header`，就不再继承 server 级同名指令，这是最容易踩的坑）；
> 2. 后端设置了 `TRUST_PROXY=1`。
>
> 否则所有请求的 IP 都会被识别为 `127.0.0.1`，全体用户挤在同一个配额桶里——
> 任何一个人连续输错密码都会导致所有人都登录不上。

### 5.5 验收安全配置是否生效

```bash
# 1) 安全响应头是否下发（应看到 X-Frame-Options 等，且不出现 X-Powered-By）
curl -sSI http://127.0.0.1:9100/api/health | grep -iE 'x-frame|content-security|x-ratelimit|x-powered-by'

# 2) 请求体限制（超限应返回 413）
curl -sS -X POST http://127.0.0.1:9100/api/register \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"$(head -c 40000 /dev/zero | tr '\0' 'a')\",\"password\":\"x\"}"

# 3) 认证限流（第 21 次应返回 429）
for i in $(seq 1 21); do
  curl -sS -o /dev/null -w "%{http_code} " -X POST http://127.0.0.1:9100/api/login \
    -H 'Content-Type: application/json' -d '{"username":"nosuchuser","password":"bad"}'
done; echo

# 4) 反代后能否取到真实客户端 IP（日志/行为不符合预期时复核 TRUST_PROXY）
sudo systemctl show bridgehub -p Environment
```

### 5.6 卸载

```bash
sudo systemctl disable --now bridgehub
sudo rm /etc/systemd/system/bridgehub.service
sudo rm -f /etc/nginx/sites-enabled/bridgehub /etc/nginx/sites-available/bridgehub
sudo systemctl reload nginx
sudo rm -rf /opt/bridgehub /var/lib/bridgehub   # 数据将一并删除，先备份！
```

## 6. 故障排查

| 现象 | 排查步骤 |
| --- | --- |
| 浏览器打不开 9100 | ① `sudo ufw status` 确认 9100 放行；② `sudo systemctl status nginx`；③ 服务器本地 `curl 127.0.0.1:9100/api/health` |
| 页面 502 Bad Gateway | 后端挂了：`sudo systemctl status bridgehub`、`sudo journalctl -u bridgehub -n 50` |
| 能开页面但联机对战不更新 | WebSocket 没通：检查 nginx 站点里 `/ws` 段的 `Upgrade`/`Connection` 头是否齐全；浏览器 DevTools → Network → WS 看握手是否 101 |
| 深链接（如 /event/daily）白屏 | 前端 `vite.config.ts` 的 `base` 必须是 `'/'`（相对路径 `./` 会导致深层路由资源 404），改后重新打包部署 |
| 注册/登录全部失败 | 检查数据目录权限：`sudo ls -l /var/lib/bridgehub` 应属 `www-data`；`sudo chown -R www-data:www-data /var/lib/bridgehub` |
| 登录提示「操作过于频繁」（429） | ① 确认是否真的在高频重试，等待惩罚期结束；② 若**所有人**都被限，说明后端只看到 `127.0.0.1`——检查 `TRUST_PROXY=1` 与 Nginx `/ws`/全局转发头（见 5.5 节） |
| 联机对战连不上，且日志提示「连接过于频繁」 | WebSocket 接入限流触发：检查是否有异常客户端刷连接；确认 Nginx `/ws` 块已重复声明 `X-Forwarded-For` |
| 请求体过大被拒（413） | 正常行为，默认上限 32KB。确需放宽时调 `JSON_LIMIT` 环境变量 |
| 每日赛成绩丢失 | 成绩在 `daily.json`，服务重启不丢；检查是否有备份被误覆盖 |
| SSH 突然登不上（认证卡住） | 高频连接可能触发临时锁定，等待 2–5 分钟再试；确认账号未被 faillock 锁定（`sudo faillock --user <名> --reset`） |
| 端口被占用 | `sudo ss -tlnp \| grep -E '9100\|8100'` 找出占用进程后处理 |

## 7. 安全说明

### 7.1 已实施的防护

- 密码使用 **scrypt**（随机盐 + `timingSafeEqual` 定时安全比较）存储，数据文件不落明文密码
- REST 请求体限制 32KB，超限返回 413
- 下发安全响应头（防点击劫持、MIME 嗅探、XSS、Spectre 类攻击），隐藏技术栈指纹
- 按 IP 的滑动窗口限流 + 指数退避惩罚，覆盖 REST 与 WebSocket
- 登录失败文案统一，防止账号枚举
- 运行时数据目录（`app/data/`）已加入 `.gitignore`，不会被提交进版本库

### 7.2 仍需人工处理的事项

| 项目 | 建议 |
| --- | --- |
| 传输加密 | 对外公网开放前务必上 HTTPS（Let's Encrypt），并设 `BEHIND_HTTPS=1` 下发 HSTS |
| **历史泄露数据** | 若早期版本的 `users.json` 曾被提交过仓库，需用 `git filter-repo` / BFG 清除历史记录，并强制已注册用户改密码 |
| 凭证管理 | GitHub Token、服务器私钥、生产 `users.json` 均不得出现在聊天记录、日志或仓库中；轮换后立即吊销旧凭证 |
| 邮箱验证 | 当前无邮箱验证，开放注册存在被批量注册的风险，建议加校验或将注册改为邀请制 |
| 存储升级 | JSON 文件存储为演示级实现，量上来后建议迁移 SQLite / PostgreSQL |
| 数据备份 | 定期备份 `/var/lib/bridgehub/`（可加入 crontab，例如每天 02:17 打包到 `~/backup/`） |

### 7.3 升级到 v1.7.0 的注意事项

1. 部署完成后**必须复核** `TRUST_PROXY=1` 是否随 systemd 单元生效（`systemctl show bridgehub -p Environment`）
2. 同步更新 Nginx 配置（`/ws` 块的转发头），然后 `nginx -t && systemctl reload nginx`
3. 用 5.5 节的四条命令验收；出问题按第 6 章排查
4. 数据文件格式未变更，**无需迁移**，用户数据不受影响

## 8. 当前生产实例信息（2026-10-14 部署）

当前共有两台生产实例，软件栈与目录结构完全一致（同一发布包 `bridgehub-release.tar.gz`），各自独立持有用户数据：

### 8.1 实例一：192.168.0.212

| 项目 | 值 |
| --- | --- |
| 服务器 | `192.168.0.212`（Ubuntu 24.04.5 LTS, x86_64） |
| 访问入口 | `http://192.168.0.212:9100/` |
| Node.js | v22.23.3（`/usr/local`） |
| 应用目录 | `/opt/bridgehub/app` |
| 数据目录 | `/var/lib/bridgehub` |

| 反代服务 | `nginx.service`，站点配置 `/etc/nginx/sites-available/bridgehub` |
| 防火墙 | ufw：仅放行 22/tcp 与 9100/tcp |

### 8.2 实例二：192.168.20.8

| 访问入口 | `http://192.168.20.8:9100/` |
