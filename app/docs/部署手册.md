# 桥牌汇 BridgeHub · 部署手册

> 适用版本：2026-10 版（前后端一体 + Nginx 反代架构）
> 目标环境：Ubuntu 22.04 / 24.04 LTS（本文以 24.04 为准）

---

## 1. 架构总览

```
用户浏览器（手机 / 平板 / PC）
        │
        ▼  TCP 9100（唯一对外 Web 端口）
┌─────────────────────────────────────┐
│ Nginx 1.24（systemd: nginx.service）│
│  /        → 反代后端（前端页面）     │
│  /assets/ → 反代 + 30 天缓存 + gzip │
│  /api/    → 反代（REST 账号接口）    │
│  /ws      → 反代 + WebSocket 升级    │
└──────────────┬──────────────────────┘
               ▼  127.0.0.1:8100（仅回环）
┌─────────────────────────────────────┐
│ BridgeHub 后端（systemd: bridgehub）│
│  Node 22 + Express 5 + ws           │
│  · dist/         前端静态产物        │
│  · dist-server/  后端 bundle        │
│  · /var/lib/bridgehub/  数据目录     │
│    ├─ users.json   账号与会话        │
│    └─ daily.json   每日双人赛成绩    │
└─────────────────────────────────────┘
```

对外防火墙（ufw）只放行两个端口：

| 端口 | 用途 |
| --- | --- |
| 22/tcp | SSH 管理 |
| 9100/tcp | Web 访问（Nginx） |

后端的 8100 端口仅监听本机回环，外部不可直连。

## 3. 全新部署（在一台干净的 Ubuntu 上）

### 3.1 准备发布包（在开发机上执行）

```bash
cd app
npm install                 # 首次需要
npm run build               # 前端：tsc 类型检查 + vite 构建到 dist/
npm run build:server        # 后端：esbuild 打包到 dist-server/index.js

# 组装发布包
rm -rf release bridgehub-release.tar.gz && mkdir -p release
cp -r dist release/dist
cp -r dist-server release/dist-server
cp deploy/bridgehub.service release/
cat > release/package.json <<'EOF'
{
  "name": "bridgehub-server",
  "private": true,
  "type": "module",
  "scripts": { "start": "node dist-server/index.js" },
  "dependencies": { "express": "^5.2.1", "ws": "^8.21.3" }
}
EOF
tar -czf bridgehub-release.tar.gz -C release .
```

### 3.2 上传到服务器

```bash
scp bridgehub-release.tar.gz deploy/setup-bridgehub.sh deploy/setup-nginx.sh deploy/nginx.conf user@<服务器IP>:/tmp/
# 注意：nginx.conf 上传为目标脚本期望的文件名
ssh user@<服务器IP> 'mv /tmp/nginx.conf /tmp/bridgehub-nginx.conf'
```

### 3.3 执行部署脚本（服务器上，需 sudo）

```bash
# 第一步：应用本体（装 Node 22 → 解压到 /opt/bridgehub/app → 装依赖 → 注册 systemd）
sudo bash /tmp/setup-bridgehub.sh

# 第二步：Nginx 反向代理（装 nginx → 站点配置 listen 9100 → 防火墙放行 9100）
sudo bash /tmp/setup-nginx.sh
```

两个脚本都是**幂等**的：重复执行只会更新到最新发布包并重启服务。

### 3.4 验证

```bash
curl http://127.0.0.1:9100/api/health
# 期望输出：{"ok":true,"name":"BridgeHub","time":"..."}
```

浏览器访问 `http://<服务器IP>:9100/` 即可。

## 4. 日常更新版本

代码更新后，只需在开发机重新执行 3.1（打包）→ 3.2（上传）→ 然后服务器上：

```bash
sudo bash /tmp/setup-bridgehub.sh
```

脚本会重新解压、安装依赖并 `systemctl restart bridgehub`。Nginx 配置无需变动。
**用户数据不受影响**（数据在 `/var/lib/bridgehub/`，不在应用目录内）。

## 5. 运维操作

### 5.1 服务管理

```bash
sudo systemctl status bridgehub      # 后端状态
sudo systemctl restart bridgehub     # 重启后端
sudo journalctl -u bridgehub -f      # 实时日志
sudo nginx -t                        # 校验 nginx 配置
sudo systemctl reload nginx          # 热加载 nginx
```

### 5.2 数据备份与迁移

只需备份数据目录中的两个文件：

```bash
sudo cp /var/lib/bridgehub/users.json /var/lib/bridgehub/daily.json ~/backup/
```

迁移到新服务器：先完成全新部署，再把这两个文件覆盖到 `/var/lib/bridgehub/`，
`sudo systemctl restart bridgehub` 即可。

### 5.3 环境变量（改 `/etc/systemd/system/bridgehub.service` 后需 `daemon-reload` + `restart`）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8100` | 后端监听端口（配合 nginx 无需改） |
| `BRIDGEHUB_DATA` | `server/data` | 数据目录，生产为 `/var/lib/bridgehub` |
| `BOT_BID_MS` / `BOT_PLAY_MS` / `TRICK_CLEAR_MS` | `650` / `750` / `1100` | AI 行动节奏（毫秒），压测时可调小 |

### 5.4 卸载

```bash
sudo systemctl disable --now bridgehub
sudo rm /etc/systemd/system/bridgehub.service
sudo rm -f /etc/nginx/sites-enabled/bridgehub /etc/nginx/sites-available/bridgehub
sudo systemctl reload nginx
sudo rm -rf /opt/bridgehub /var/lib/bridgehub   # 数据将一并删除，先备份！
```

## 6. 故障排查

| 现象 | 排查步骤 |
| --- | --- |
| 浏览器打不开 9100 | ① `sudo ufw status` 确认 9100 放行；② `sudo systemctl status nginx`；③ 服务器本地 `curl 127.0.0.1:9100/api/health` |
| 页面 502 Bad Gateway | 后端挂了：`sudo systemctl status bridgehub`、`sudo journalctl -u bridgehub -n 50` |
| 能开页面但联机对战不更新 | WebSocket 没通：检查 nginx 站点里 `/ws` 段的 `Upgrade`/`Connection` 头是否齐全；浏览器 DevTools → Network → WS 看握手是否 101 |
| 深链接（如 /event/daily）白屏 | 前端 `vite.config.ts` 的 `base` 必须是 `'/'`（相对路径 `./` 会导致深层路由资源 404），改后重新打包部署 |
| 注册/登录全部失败 | 检查数据目录权限：`sudo ls -l /var/lib/bridgehub` 应属 `www-data`；`sudo chown -R www-data:www-data /var/lib/bridgehub` |
| 每日赛成绩丢失 | 成绩在 `daily.json`，服务重启不丢；检查是否有备份被误覆盖 |
| SSH 突然登不上（认证卡住） | 高频连接可能触发临时锁定，等待 2–5 分钟再试；确认账号未被 faillock 锁定（`sudo faillock --user <名> --reset`） |
| 端口被占用 | `sudo ss -tlnp \| grep -E '9100\|8100'` 找出占用进程后处理 |

## 7. 安全说明

- 密码使用 **scrypt** 加盐散列存储，数据库文件不落明文密码
- 后端接口无速率限制与邮箱验证，属演示级实现；对外公网开放前建议：上 HTTPS（Let's Encrypt）、给 `/api/register` 加限流、更换更长的会话令牌过期策略
- 建议仅在内网/办公网使用，或配合域名 + HTTPS 后再公网开放
- 定期备份 `/var/lib/bridgehub/`（可加入 crontab，例如每天 02:17 打包到 `~/backup/`）

## 8. 当前生产实例信息（2026-10-14 部署）

当前共有两台生产实例，软件栈与目录结构完全一致（同一发布包 `bridgehub-release.tar.gz`），各自独立持有用户数据：

### 8.1 实例一：192.168.0.212

| 项目 | 值 |
| --- | --- |
| 服务器 | `192.168.0.212`（Ubuntu 24.04.5 LTS, x86_64） |
| 访问入口 | `http://192.168.0.212:9100/` |
| Node.js | v22.23.3（`/usr/local`） |
| 应用目录 | `/opt/bridgehub/app` |
| 数据目录 | `/var/lib/bridgehub` |
| 后端服务 | `bridgehub.service`（www-data 运行，开机自启，崩溃自动重启） |
| 反代服务 | `nginx.service`，站点配置 `/etc/nginx/sites-available/bridgehub` |
| 防火墙 | ufw：仅放行 22/tcp 与 9100/tcp |

### 8.2 实例二：192.168.20.8

| 项目 | 值 |
| --- | --- |
| 服务器 | `192.168.20.8`（主机名 ubuntu22-webchat，Ubuntu 24.04.5 LTS, x86_64） |
| 管理账号 | `administrator`（sudo 需密码） |
| 访问入口 | `http://192.168.20.8:9100/` |
| Node.js | v22.23.3（`/usr/local`；服务器无法直连 nodejs.org，安装包经本地上传后离线解压安装） |
| 应用目录 | `/opt/bridgehub/app` |
| 数据目录 | `/var/lib/bridgehub` |
| 后端服务 | `bridgehub.service`（www-data 运行，开机自启，崩溃自动重启） |
| 反代服务 | `nginx.service` 1.24.0，站点配置 `/etc/nginx/sites-available/bridgehub` |
| 防火墙 | ufw 未启用（inactive），9100 由 nginx 监听，8100 仅回环 |

### 8.3 上线验证记录（两实例均通过）

| 检查项 | 期望 | 结果 |
| --- | --- | --- |
| `GET /api/health` | 返回 `{"ok":true,"name":"BridgeHub",...}` | 通过 |
| 首页 `GET /` | HTTP 200，标题「桥牌汇 · BridgeHub」 | 通过 |
| `GET /ws`（带 Upgrade 头） | 返回 101 Switching Protocols | 通过 |

> 注意：两台实例的账号与每日赛成绩**互不相通**（数据各自存在本机 `/var/lib/bridgehub/`）。
> 若需合并或迁移，按 5.2 节备份/恢复两个 JSON 文件即可。
